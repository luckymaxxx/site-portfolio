# Сайт-портфоліо

Статичний двомовний сайт: головна, детальні сторінки-кейси по проектах і резюме з друком у PDF.
Увесь контент живе в Markdown-файлах із типізованим frontmatter — щоб додати проект, код чіпати не треба.

## Стек

| Шар        | Рішення                                                             |
| ---------- | ------------------------------------------------------------------- |
| Фреймворк  | Astro 5, статичний білд, без SSR і адаптера                         |
| Мова       | TypeScript, strict                                                  |
| Стилі      | Tailwind CSS v4 через `@tailwindcss/vite`, токени в `@theme inline` |
| Контент    | Astro Content Collections + Zod                                     |
| i18n       | Вбудований роутинг Astro: `en` на корені, `uk` під `/uk/`           |
| Інтерактив | Три невеликі інлайнові скрипти: тема, «виділити блок», друк         |
| Графіки    | Власні компоненти на CSS, без бібліотек                             |
| Хостинг    | Vercel (статика, автовизначення Astro)                              |

У зібраному бандлі немає жодного JS-файлу — тільки CSS і HTML.

## Запуск

```bash
pnpm install
pnpm dev          # http://localhost:4321
```

Інші команди:

```bash
pnpm build        # збірка у dist/
pnpm preview      # локальний перегляд зібраного сайту
pnpm check        # типи + діагностика .astro
pnpm lint         # ESLint
pnpm format       # Prettier
```

## Як додати новий проект

**1. Скопіюй шаблони.** Для кожної мови свій файл:

```bash
cp src/content/projects/_TEMPLATE.uk.md src/content/projects/my-project.uk.md
cp src/content/projects/_TEMPLATE.en.md src/content/projects/my-project.en.md
```

Ім'я файлу — `<slug>.<мова>.md`. Файли, що починаються з `_`, у білд не потрапляють.

**2. Заповни `slug` і `lang`.** `slug` має бути **однаковий** в обох файлах — саме він стає адресою
(`/projects/my-project` і `/uk/projects/my-project`). `lang` — `uk` або `en`, відповідно до файлу.

**3. Заповни решту frontmatter.** Над кожним полем у шаблоні є коментар: що це, який формат і приклад.
Обов'язкові поля позначені. Секції, для яких поле лишилось порожнім (`''` або `[]`), просто не рендеряться —
кейс без графіків або без глосарію виглядає нормально.

**4. Поклади обкладинку.** Файл у `public/projects/`, шлях у полі `cover`:

```yaml
cover: '/projects/my-project.png'
```

Розміри: обкладинка **1600×900** (16:9), OG-зображення **1200×630** у `public/og/`.
PNG або JPG, бажано до 300 КБ.

**5. Прибери `draft: true`** і запусти `pnpm dev`. Кейс з'явиться на головній і матиме власну сторінку.
Порядок карток задає поле `order` (менше = вище), а `featured: true` робить картку великою.

Якщо у frontmatter помилка — `pnpm build` впаде і назве файл та поле.

### Якщо перекладу немає

Можна залити лише одну мовну версію. Кейс усе одно з'явиться в обох мовах — з поміткою,
що доступний лише мовою оригіналу.

## Профіль і резюме

`src/content/profile/uk.md` і `en.md` — ім'я, контакти, навички, досвід, освіта, мови.
З цих файлів збирається головна сторінка і `/cv`. Тіло файлу (текст під frontmatter) стає
секцією «Про себе» в резюме.

Кнопка **«Зберегти у PDF»** на `/cv` викликає діалог друку браузера.
Друковану версію описує `src/styles/print.css`: хедер, футер і перемикачі ховаються,
палітра примусово світла, поля сторінки 14 мм.

## Структура

```
src/
├── content.config.ts     ← Zod-схеми колекцій: єдине джерело правди по полях
├── content/
│   ├── projects/         ← кейси: <slug>.<lang>.md + шаблони _TEMPLATE.*
│   └── profile/          ← профіль: uk.md, en.md
├── i18n/                 ← словник рядків інтерфейсу та хелпери шляхів
├── lib/                  ← вибірки контенту й інлайновий Markdown
├── styles/               ← global.css (токени, типографіка) і print.css
├── layouts/              ← BaseLayout (head, SEO, хедер, футер) і ProjectLayout
├── components/           ← компоненти кейсу й головної
└── pages/                ← [...lang]/ дає /, /uk/, /cv, /uk/cv, /projects/…
```

Усі тексти інтерфейсу — у `src/i18n/ui.ts`. У компонентах хардкоду немає.

## Тема

Три стани: системна, примусово світла, примусово темна. Вибір зберігається в `localStorage`
і застосовується інлайновим скриптом у `<head>` до першого рендеру, тому спалаху не буває.
Уся палітра визначена тричі — у голому `:root`, у `prefers-color-scheme: dark` і в `[data-theme]`,
щоб жоден колір не існував лише всередині media-блоку.

## Деплой

Vercel визначає Astro сам: **Framework preset** Astro, build `pnpm build`, output `dist`.
Конфігураційний файл не потрібен.

Перед першим деплоєм:

1. Постав реальний домен у `astro.config.mjs` (константа `SITE`) — від нього залежать
   canonical, hreflang, OG-теги і `sitemap-index.xml`.
2. Заповни `src/content/profile/uk.md` і `en.md`.
3. За бажанням поклади OG-зображення в `public/og/` і пропиши шляхи в полях `ogImage`.

## Відхилення від брифу

Два свідомі відступи, обидва задокументовані в коді:

- **`--ink-faint` у світлій темі** — `#61716e` замість `#7d8c89`. Оригінальне значення дає
  контраст 3.26:1 на фоні сторінки, а цим токеном набрані дрібні моношрифтові мітки.
  Нове значення — 4.76:1, тобто WCAG AA. Відтінок збережено.
- **Сітка «ключових напрямків»** — hairline-решітка зроблена рамками на блоках, а не
  `gap: 2px` на фоні `--line`. З gap порожня клітинка останнього ряду ставала суцільною
  сірою плиткою, коли кількість блоків не кратна кількості колонок.
